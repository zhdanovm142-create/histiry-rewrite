# План по этапам: CDP/мультисессии/безопасный patching/продуктивность

## Stage 1 — Базовая сессия: CDP attach → prompt send → response extraction

### Scope
- Подключение к уже запущенному браузеру через CDP (Chrome DevTools Protocol).
- Выбор целевой вкладки/контекста.
- Отправка одного prompt в целевой UI.
- Извлечение и структурирование ответа в машинно-читаемом виде (JSON/текст + метаданные).

### Definition of Done (DoD)
- Успешный attach к CDP endpoint в >= 95% попыток на тестовом окружении.
- Prompt может быть отправлен без ручного вмешательства.
- Ответ корректно извлекается и сохраняется в унифицированной структуре:
  - `session_id`
  - `prompt_id`
  - `prompt_text`
  - `response_text`
  - `timestamps` (send/receive)
  - `source_tab`
- Обработка базовых ошибок:
  - недоступен CDP endpoint;
  - целевая вкладка не найдена;
  - таймаут ответа.
- Есть минимальный CLI/скрипт для локального запуска end-to-end.

### Демо-сценарий
1. Поднять Chrome с включённым remote debugging портом.
2. Запустить команду вида `agent run --stage1 --prompt "Привет"`.
3. Показать в логах:
   - attach к CDP;
   - отправку prompt;
   - получение ответа.
4. Открыть сохранённый артефакт ответа (JSON) и проверить поля.

## Stage 2 — Multi-session: dashboard cards, queues, periodic screenshots

### Scope
- Поддержка нескольких параллельных сессий.
- Dashboard со статусными карточками по каждой сессии.
- Очередь задач/промптов по сессиям (FIFO + приоритет при необходимости).
- Периодические скриншоты состояния сессий/вкладок.

### Definition of Done (DoD)
- Одновременная стабильная работа минимум 5 параллельных сессий.
- Dashboard отображает по каждой сессии:
  - статус (`idle/running/error`),
  - текущую задачу,
  - время последнего события,
  - счётчик обработанных задач,
  - ссылку на последний screenshot.
- Очередь поддерживает:
  - enqueue/dequeue,
  - retry с лимитом,
  - DLQ (dead-letter queue) для неуспешных задач.
- Скриншоты делаются по расписанию (например, каждые 30–60 сек) и сохраняются с привязкой к session/task id.
- Есть базовые метрики:
  - latency на задачу,
  - success/fail rate,
  - queue depth.

### Демо-сценарий
1. Запустить 5 сессий и отправить пакет из 20 задач.
2. На dashboard показать изменение статусов в реальном времени.
3. Искусственно «сломать» одну задачу (таймаут/ошибка) и показать retry + DLQ.
4. Открыть папку/хранилище скриншотов и показать периодические снимки по конкретной сессии.

## Stage 3 — Safe patching: diff preview, manual approve, apply + rollback metadata

### Scope
- Безопасное внесение изменений в код/тексты через управляемый pipeline.
- Предпросмотр diffs до применения.
- Ручное подтверждение (manual approve) перед `apply`.
- Хранение метаданных для rollback.

### Definition of Done (DoD)
- Любой patch проходит состояния:
  1) `generated`
  2) `previewed`
  3) `approved/rejected`
  4) `applied` (или `aborted`)
- Diff preview показывает:
  - файл,
  - контекст изменений,
  - автора/инициатора,
  - оценку риска (простая эвристика: количество файлов/строк/критичность путей).
- Без явного manual approve применение невозможно (hard gate).
- При apply фиксируются rollback-метаданные:
  - patch id,
  - base commit/hash,
  - изменённые файлы,
  - timestamp,
  - оператор,
  - способ отката.
- Rollback запускается одной командой и возвращает состояние к base commit/hash.
- В audit-логе сохраняется цепочка `preview → approve → apply/rollback`.

### Демо-сценарий
1. Сгенерировать patch на 2–3 файла.
2. Показать diff preview UI/CLI.
3. Отклонить patch (reject) и убедиться, что ничего не применилось.
4. Повторно сгенерировать, сделать approve и apply.
5. Запустить rollback и показать восстановление исходного состояния.

## Stage 4 — Productivity: hotkeys, VSCode/local workflow hooks

### Scope
- Горячие клавиши для частых действий (attach, send prompt, snapshot, approve patch).
- Интеграция с VSCode (commands/tasks/status bar/панель).
- Локальные workflow hooks (pre-run, post-run, pre-apply checks).

### Definition of Done (DoD)
- Настроен и задокументирован минимальный набор hotkeys:
  - запуск/остановка сессии,
  - отправка prompt,
  - открытие последнего ответа,
  - открытие diff preview,
  - approve/reject patch.
- VSCode-интеграция позволяет выполнить ключевые сценарии без терминала (минимум 3 команды).
- Hooks поддерживают:
  - pre-run проверку окружения,
  - pre-apply валидации (lint/tests/политики),
  - post-run публикацию артефактов/логов.
- Сокращение времени на типовой цикл (attach → prompt → ответ → patch) минимум на 30% относительно Stage 1 baseline.
- Пользовательская документация (quickstart + cheatsheet hotkeys) готова и проверена на 1–2 пилотных пользователях.

### Демо-сценарий
1. В VSCode запустить сессию командой из Command Palette.
2. Отправить prompt hotkey’ем, открыть ответ в боковой панели.
3. Инициировать patch, посмотреть diff preview, сделать approve hotkey’ем.
4. Показать срабатывание pre-apply hook (например, lint) и успешное применение.
5. Сравнить длительность цикла с baseline и показать метрику ускорения.

## Общие критерии готовности программы
- Наблюдаемость: логи, метрики, трассировка событий на всех stages.
- Надёжность: документированные retry/timeout/panic recovery стратегии.
- Безопасность: ручные gates на рисковые операции, аудит изменений.
- Операционность: runbook для локального и командного использования.
